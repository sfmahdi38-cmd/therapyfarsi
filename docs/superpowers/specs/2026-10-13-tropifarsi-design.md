# طرح کامل TropiFarsi (tropifarsi.com)

**تاریخ:** ۲۰۲۶-۱۰-۱۳
**نسخه:** ۳ (بعد از دو دور نقد بیرونی؛ تصمیم‌های باز را صاحب سایت به سازنده سپرده)
**وضعیت:** تأیید شده برای ساخت

---

## ۱. خلاصه

TropiFarsi یه سایت نوبت‌دهی آنلاینه که ایرانی‌های خارج از کشور باهاش از **روان‌پزشک‌ها و روان‌درمانگرهای فارسی‌زبانِ داخل ایران** وقت مشاوره‌ی تصویری می‌گیرن.

سایت مثل یه **آژانس** کار می‌کنه:
- مراجع پول رو به صاحب سایت می‌ده.
- جلسه داخل خود سایت برگزار می‌شه.
- صاحب سایت سهم هر دکتر رو جدا تسویه می‌کنه.
- همه‌ی نوبت‌ها، حضورها، پرداخت‌ها، برگشت‌ها و تسویه‌ها توی یه پنل قابل پیگیریه.

**معیار موفقیت:**
- مراجع بدون کمک کسی دکتر پیدا کنه، پرداخت کنه و جلسه رو برگزار کنه.
- صاحب سایت در هر لحظه بدونه چه جلسه‌هایی برگزار شده، چقدر درآمد داشته و به هر دکتر چقدر بدهکاره.
- همه‌ی این‌ها **بدون دست بردن دستی توی دیتابیس** انجام بشه.

**حس ظاهری:** ساده، آروم، مرتب و قابل اعتماد. فارسی و راست‌به‌چپ زبان اصلیه، و نسخه‌ی انگلیسی هم داره.

## ۲. تصمیم‌ها

| موضوع | تصمیم |
|---|---|
| پرداخت | Stripe به اسم صاحب سایت. کد پرداخت پشت ماژول جدای `payments` نوشته می‌شه تا بشه ارائه‌دهنده رو عوض کرد |
| ارز | همه‌ی قیمت‌ها به **دلار آمریکا**. همه‌ی مبلغ‌ها به **سنت** و به‌صورت عدد صحیح ذخیره می‌شن |
| قیمت | قیمت هر دکتر رو صاحب سایت تعیین می‌کنه. قیمت **عمومیه** و روی پروفایل نمایش داده می‌شه |
| سهم دکتر | درصد (`share_bps`، از ۰ تا ۱۰۰۰۰) یا مبلغ ثابت (`share_fixed_cents`). سهمی که بعد از کم شدن کارمزد تخمینی Stripe سهم آژانس رو منفی کنه، ذخیره نمی‌شه |
| جلسه | تماس تصویری داخل سایت، با حالت «فقط صدا». ارائه‌دهنده بعد از قدم ۰-الف انتخاب می‌شه |
| نوع خدمت در مرحله‌ی ۱ | **مشاوره و روان‌درمانی گفتگومحور.** روان‌پزشک‌ها هم ارائه‌ی خدمت می‌کنن، ولی سایت **نسخه صادر نمی‌کنه** (بخش ۴-۹) |
| نوبت‌دهی | دکترها برنامه‌ی هفتگی می‌ذارن. نوبت بعد از پرداخت، خودکار قطعی می‌شه |
| جابه‌جایی | **فقط با همون دکتر.** همون ردیف نوبت جابه‌جا می‌شه، پس پرداخت هم همون یکی می‌مونه |
| کنسلی و اختلاف | طبق بخش ۴-۸ |
| مراجع‌ها | فقط **بزرگسال (۱۸+)**، فقط **جلسه‌ی فردی** |
| زبان | فارسی (پیش‌فرض) + انگلیسی. اگه انگلیسی آماده نبود، انتشار فارسی منتظرش نمی‌مونه |
| زیرساخت | سایت روی Cloudflare Workers، دیتابیس و ورود روی Supabase (منطقه‌ی فرانکفورت) |
| پول واقعی | Stripe تا تصمیم صاحب سایت (بخش ۸) فقط روی **حالت تست** کار می‌کنه |

## ۴. مسیر مراجع و قواعد نوبت

### ۴-۱. صفحه‌ی اصلی

**هدر**
- یه جمله‌ی اصلی و دو دکمه: «کمکم کن دکتر مناسب رو پیدا کنم» و «دیدن دکترها».
- ویدیوی بی‌صدا با حجم زیر ۳ تا ۵ مگابایت که با تأخیر لود می‌شه و یه عکس ثابت جایگزینشه.
- اگه کاربر «کاهش حرکت» رو روشن کرده باشه، فقط عکس نمایش داده می‌شه.

**بعد از هدر**
- سه قدم کار
- دسته‌بندی‌ها: اضطراب، افسردگی، غم مهاجرت، تنهایی، مشکلات رابطه، خواب
- نظرها
- سؤال‌های متداول
- ساعت‌های پاسخ‌گویی پشتیبانی

### ۴-۲. پرسشنامه

**سؤال‌ها:** ۵ یا ۶ سؤال درباره‌ی موضوع اصلی، دکتر خانم یا آقا، منطقه‌ی زمانی، سابقه‌ی مصرف دارو، و یه سؤال غربالگری خطر.

**غربالگری خطر**
- متن سؤال غربالگری و اقدام بعدیش رو **مسئول بالینی** تعیین می‌کنه. این نقش رو یکی از دکترهای ارشد داره که صاحب سایت انتخابش می‌کنه.
- تا اون موقع، این رفتار پیش‌فرض اجرا می‌شه:
  1. صفحه‌ی شرایط اضطراری با شماره‌ی اورژانس کشور مراجع نمایش داده می‌شه.
  2. مراجع باید تأیید کنه که این صفحه رو دیده.
  3. بعد می‌تونه رزرو رو ادامه بده.
  4. نوبتش برای دکتر و ادمین علامت‌گذاری می‌شه.
- اینکه ادامه‌ی رزرو مجاز باشه یا نه، یه تنظیمه (`risk_allows_booking`) که پیش‌فرضش `true` است.

**خروجی**
- خروجی پرسشنامه **تشخیص نیست.** متنش این‌طوریه: «این دکترها با موضوعی که گفتی کار می‌کنن».

**پرسشنامه‌ی مهمان**
- کوکی **فقط یه شناسه‌ی تصادفی** نگه می‌داره.
- جواب‌ها رمزگذاری‌شده توی دیتابیس ذخیره می‌شن، کنار هش همون شناسه.
- موقع ثبت‌نام به حساب وصل می‌شن.
- اگه تا ۷ روز به حسابی وصل نشن، پاک می‌شن.

**پیشنهاد دکتر:** ۳ دکتر اول پیشنهاد می‌شن (روشش در بخش ۷-۹).

### ۴-۳. پروفایل دکتر
- عکس، تخصص‌ها، ویدیوی معرفی، قیمت به دلار، نظرهای تأییدشده.
- **نشان «تأیید شده»:** یعنی «هویت و مدرک حرفه‌ای (نوع، شماره و مرجع صدور) توسط TropiFarsi بررسی شده». تاریخ بررسی هم کنارش نوشته می‌شه.
- تقویم وقت خالی، به ساعت محلی مراجع.

### ۴-۴. ثبت‌نام و ورود

**روش ورود**
- **کد ۶ رقمی ایمیلی** که روی خود tropifarsi.com وارد می‌شه.
- ایمیل **هیچ لینکی** به دامنه‌ی دیگه نداره و فقط کد داخلشه.
- مراجع‌ها می‌تونن با گوگل هم وارد بشن. دکترها و ادمین فقط با کد ایمیلی وارد می‌شن.

**ثبت‌نام مراجع**
- مراجع موقع ثبت‌نام تأیید می‌کنه که بالای ۱۸ ساله.

**رضایت‌نامه‌ها**
- موقع رزرو، قوانین و رضایت‌نامه تیک زده می‌شن.
- نسخه‌ی متن و زمان پذیرش ثبت می‌شه.

### ۴-۵. قواعد رزرو

| قاعده | پیش‌فرض (توی تنظیمات قابل تغییره) |
|---|---|
| حداقل فاصله‌ی رزرو تا جلسه | ۱۲ ساعت |
| حداکثر فاصله‌ی رزرو تا جلسه | ۳۰ روز |
| مهلت پرداخت (نگه‌داشتن ساعت) | ۳۰ دقیقه. مهلت Checkout توی Stripe هم دقیقاً همین زمان تنظیم می‌شه |
| تعداد نوبت نگه‌داشته‌شده‌ی هم‌زمان برای هر مراجع | ۱ |
| مهلت کنسلی با برگشت پول | ۲۴ ساعت |
| مهلت ثبت «درخواست بررسی» بعد از جلسه | ۴۸ ساعت |
| حد برگزاری (حضور هم‌زمان) | ۵۰٪ طول جلسه |
| انتظار دکتر قبل از ثبت غیبت مراجع | ۱۵ دقیقه |

- **فاصله‌ی استراحت دکتر** جزو زمان اشغال حساب می‌شه.
- **رزرو بین ۱۲ تا ۲۴ ساعت قبل از جلسه:**
  - همون لحظه‌ی خرید، دیگه برگشت پول نداره.
  - مراجع باید جداگانه تیک بزنه: «می‌دونم این نوبت قابل برگشت نیست».
  - بدون این تیک، صفحه‌ی پرداخت ساخته نمی‌شه.
- **تغییر برنامه‌ی هفتگی دکتر:** نوبت‌های قطعی دست نمی‌خورن، ولی به دکتر هشدار داده می‌شه.
- **نمایش ساعت خالی:** ساعتی که مهلت پرداختش گذشته، توی تقویم **فوراً آزاد** نشون داده می‌شه. منتظر هیچ کار زمان‌داری نمی‌مونه.

### ۴-۶. پرداخت
- فقط کارت، Apple Pay و Google Pay قبول می‌شه (پرداخت فوری).
- نوبت فقط با تأیید خود Stripe قطعی می‌شه (بخش ۷-۷).
- بعد از قطعی شدن، ایمیل تأیید با فایل `.ics` فرستاده می‌شه.

### ۴-۷. روز جلسه و بعد از اون

**یادآوری‌ها**
- یادآوری ۲۴ ساعته و ۱ ساعته فرستاده می‌شه.
- یادآوری‌ای که زمانش گذشته باشه **ساخته نمی‌شه.** مثلاً برای نوبتی که ۱۵ ساعت مونده، یادآوری ۲۴ ساعته ساخته نمی‌شه.

**ورود به جلسه**
- دکمه‌ی ورود از ۱۰ دقیقه قبل فعال می‌شه.
- قبل از ورود، دوربین و میکروفون تست می‌شن.
- داخل تماس، دکمه‌ی **«فقط صدا»** هست.

**دکمه‌ی «مشکل اتصال دارم»** (یه کمک فنیه، نه شکایت مالی)
- راه‌حل‌های سریع رو نشون می‌ده، مثل رفرش و رفتن به حالت فقط صدا.
- لینک واتس‌اپ و ساعت‌های پشتیبانی رو نشون می‌ده.
- یه `issue` از نوع `connection` ثبت می‌کنه و به ادمین خبر می‌ده.
- **روی نتیجه‌ی جلسه اثر مستقیم نداره** (بخش ۴-۸).

**فرم «درخواست بررسی»**
- مراجع یا دکتر تا ۴۸ ساعت بعد از جلسه می‌تونن پرش کنن.
- یه `issue` از نوع `dispute` ثبت می‌کنه.
- جلسه رو به `needs_review` می‌بره و ادمین تصمیم می‌گیره.

**بعد از جلسه:** مراجع امتیاز و نظر می‌ده و جلسه‌ی بعد رو رزرو می‌کنه.

**حساب مراجع:** جلسه‌ها، رسیدها، کنسلی، جابه‌جایی، درخواست بررسی، پشتیبانی.

**جابه‌جایی**
- مجازه اگه بیشتر از ۲۴ ساعت به جلسه مونده باشه، یا یکی از حالت‌های «جابه‌جایی رایگان» توی جدول ۴-۸ پیش اومده باشه.
- فقط با همون دکتر.
- زمان همون ردیف نوبت عوض می‌شه، توی یه دستور اتمیک. اگه ساعت جدید گرفته شده باشه، هیچ چیزی تغییر نمی‌کنه.
- پرداخت همونی که بود می‌مونه.
- سابقه‌ی جابه‌جایی توی `booking_reschedules` ثبت می‌شه.

### ۴-۸. نتیجه‌ی جلسه و جدول کنسلی

«زمان هم‌زمان» یعنی مدتی که هر دو طرف با هم داخل تماس بودن. این زمان از رویدادهای سرویس تماس محاسبه می‌شه و قطع و وصل‌ها رو هم در نظر می‌گیره.

**ترتیب تعیین نتیجه بعد از پایان جلسه** (اولین شرطی که درست باشه، برنده‌ست):

1. ادمین تصمیم گرفته ← تصمیم ادمین
2. `issue` از نوع `dispute` باز وجود داره ← `needs_review`
3. زمان هم‌زمان ≥ حد برگزاری ← `completed` (حتی اگه دکمه‌ی اتصال زده شده باشه)
4. دکتر وارد شده و ۱۵ دقیقه منتظر مونده، مراجع اصلاً وارد نشده ← `no_show_client`
5. مراجع وارد شده، دکتر اصلاً وارد نشده ← `no_show_doctor`
6. هر دو وارد شدن ولی زمان هم‌زمان کمتر از حد برگزاری بوده ← `partial`
7. در غیر این صورت ← `needs_review`

**جدول کنسلی و نتیجه**

| وضعیت | مراجع | دفتر دکتر |
|---|---|---|
| مراجع، بیشتر از ۲۴ ساعت قبل کنسل کنه | برگشت کامل پول یا جابه‌جایی | — |
| مراجع، کمتر از ۲۴ ساعت قبل کنسل کنه | برگشت نداره | طلب `late_cancel` |
| `no_show_client` | برگشت نداره | طلب `no_show` |
| دکتر کنسل کنه یا `no_show_doctor` | برگشت کامل پول یا جابه‌جایی رایگان (انتخاب با مراجع) | — |
| `partial` | جابه‌جایی رایگان، یا برگشت کامل اگه مراجع بخواد | — (طلب با جلسه‌ی جابه‌جاشده ثبت می‌شه) |
| `completed` | — | طلب `session` |
| `needs_review` | ادمین یکی از ردیف‌های بالا رو انتخاب می‌کنه | طبق همون ردیف |
| برگشت پول بعد از ثبت طلب | — | ادمین انتخاب می‌کنه: طلب بمونه، یا ردیف `reversal` ثبت بشه |
| اعتراض بانکی (`disputed`) | Stripe بررسی می‌کنه | ادمین انتخاب می‌کنه، مثل ردیف قبلی |

**نسخه‌ی قانون:** قانون کنسلی نسخه‌داره و نسخه‌ای که موقع رزرو فعال بوده روی نوبت ثبت می‌شه.

**کارمزد Stripe:** موقع برگشت پول، Stripe کارمزدش رو برنمی‌گردونه. این کارمزد از سهم آژانس کم می‌شه و ممکنه سهم آژانس اون جلسه منفی بشه.

### ۴-۹. دارو و نسخه
- روان‌پزشک‌ها می‌تونن ارزیابی کنن و توصیه بدن.
- اگه دکتر تشخیص بده دارو لازمه، مراجع رو برای نسخه به **پزشک محلی کشور خودش** ارجاع می‌ده.
- این موضوع روی پروفایل روان‌پزشک‌ها و توی سؤال‌های متداول شفاف نوشته می‌شه.

## ۵. پنل دکتر

ساده، فارسی، به ساعت تهران، و مناسب گوشی.

1. **ورود:**
   - حساب دکتر رو فقط ادمین می‌سازه.
   - ورود با کد ۶ رقمی ایمیلی انجام می‌شه.
2. **امروز:**
   - جلسه‌های امروز و فردا با اسم کوچک مراجع.
   - جواب‌های پرسشنامه، علامت خطر، و دکمه‌ی ورود.
3. **برنامه‌ی هفتگی:**
   - ساعت‌های کاری و روزهای مرخصی.
   - هشدار برای نوبت‌های قطعی که با برنامه‌ی جدید تداخل دارن.
4. **یادداشت شخصی:**
   - یادداشت کاری خود دکتره، نه پرونده‌ی رسمی بالینی.
   - فقط خود دکتر می‌بینه و می‌تونه ویرایش یا پاکش کنه.
5. **درآمد:**
   - ردیف‌های دفتر خودش (طلب‌ها و اصلاحیه‌ها)، تسویه‌های دریافتی و مانده.
   - دکتر **جدول پرداخت‌ها** رو نمی‌بینه: کارمزدها، برگشتی‌ها و اطلاعات کارت. قیمت جلسه که عمومیه، همون‌طور روی پروفایل نمایش داده می‌شه.
6. **کنسلی از طرف دکتر:**
   - به مراجع و ادمین خبر داده می‌شه.
   - توی آمار دکتر ثبت می‌شه.
7. **مشکل اتصال و درخواست بررسی:** مثل مراجع.

## ۶. پنل آژانس

### ۱. داشبورد
- جلسه‌های امروز.
- **مبلغ‌های ماه**، که از جدول `payments` محاسبه می‌شن و هر پرداخت فقط یه بار شمرده می‌شه:
  - کل دریافتی
  - برگشتی‌ها
  - کارمزد Stripe
  - طلب ثبت‌شده‌ی دکترها
  - **سهم آژانس** = دریافتی − برگشتی − کارمزد − طلب دکترها. این عدد قبل از هزینه‌های دیگه‌ست و «سود خالص» نیست.
- مانده‌ی هر دکتر.
- **هشدارها:** مشکل اتصال، درخواست بررسی، نوبت `needs_review`، برگشت ناموفق، اعتراض بانکی، کار ناموفق توی صف، نظر در انتظار تأیید.

### ۲. نوبت‌ها
- فیلتر بر اساس دکتر، تاریخ و هر چهار وضعیت.
- جزئیات حضور: ورود و خروج‌ها و زمان هم‌زمان.
- کارهای ادمین روی نوبت:
  - جابه‌جایی
  - کنسلی
  - برگشت پول (کامل یا جزئی)
  - تصمیم روی نوبت‌های `needs_review`

### ۳. دکترها
- ساخت حساب.
- بررسی مدرک و نشان «تأیید شده».
- تنظیم قیمت، سهم، طول جلسه و فاصله.
  - اگه سهم دکتر بعد از کارمزد تخمینی سهم آژانس رو منفی کنه، فرم خطا می‌ده و ذخیره نمی‌شه.
- پروفایل دو زبانه، فعال یا غیرفعال کردن، آمار.

### ۴. دفتر مالی دکترها
**ردیف‌های دفتر**
- `doctor_ledger_entries` فقط اضافه می‌شه؛ هیچ ردیفی ویرایش یا حذف نمی‌شه.
- هر ردیف یه `source_key` یکتا داره. این یعنی هیچ رویدادی دو بار طلب نمی‌سازه. مثلاً:
  - `session:<booking_id>`
  - `late_cancel:<booking_id>`
  - `reversal:<refund_id>`

**ثبت تسویه**
- ادمین هر پرداخت به دکتر رو ثبت می‌کنه با این اطلاعات: مبلغ دلاری، معادل **تومانی**، نرخ (تومان به ازای هر دلار)، تاریخ، عکس رسید و توضیح.

**محاسبه‌ها**
- **مانده = جمع ردیف‌های دفتر − جمع تسویه‌ها.** اگه به دکتر پول اضافه داده شده باشه، مانده منفی می‌شه و طلب‌های بعدی ازش کم می‌شن.
- **وضعیت هر طلب** (قابل پرداخت، تسویه‌ی جزئی، تسویه شده) با تخصیص خودکار تسویه‌ها به قدیمی‌ترین طلب‌ها محاسبه می‌شه. این تخصیص فقط برای نمایشه و مانده رو عوض نمی‌کنه.

### ۵. بقیه‌ی بخش‌ها
- **مراجع‌ها:** پرونده‌ی هر مراجع، جواب‌های پرسشنامه، و یادداشت داخلی ادمین. یادداشت‌های دکتر اینجا نمایش داده نمی‌شن.
- **نظرها:**
  - مراجع جداگانه تیک می‌زنه که نظرش منتشر بشه.
  - نظر با اسم مستعار نمایش داده می‌شه.
  - ادمین اطلاعات حساس رو حذف می‌کنه و نظر رو تأیید یا رد می‌کنه.
- **گزارش ماهانه:** با خروجی CSV.
- **سابقه‌ی تغییرات:** هر عمل مالی و هر تغییر نوبت ثبت می‌شه.
- **تنظیمات:**
  - قواعد ۴-۵ و قانون کنسلی (نسخه‌دار)
  - `risk_allows_booking`
  - کارمزد تخمینی Stripe
  - شماره و ساعت‌های واتس‌اپ
  - متن ایمیل‌ها
- **تأیید دو مرحله‌ای:** اجباریه و روی خود دیتابیس اعمال می‌شه (شرط `aal2` توی RLS).

  - اجرای صف کارها

**جدول‌های حساس**

- `doctor_notes` هیچ policy‌ای برای ادمین نداره.

### ۷-۶. تابع‌های اتمیک

هر کدوم از این تابع‌ها یه تابع Postgres است که توی یه تراکنش اجرا می‌شه.

**`hold_slot(client, doctor, starts_at)`**
1. قواعد ۴-۵ رو چک می‌کنه.
2. نوبت‌های `held` منقضی‌شده‌ای که با این بازه تداخل دارن رو `expired` می‌کنه.
3. چک می‌کنه مراجع نوبت `held` معتبر دیگه‌ای نداشته باشه.
4. ردیف جدید رو با قیمت، سهم دکتر و نسخه‌ی قانون ثابت‌شده درج می‌کنه.
5. اگه به constraint تداخل بخوره، خطای `slot_taken` برمی‌گردونه.

**`confirm_payment(stripe_event)`**
1. شناسه‌ی رویداد رو توی `stripe_events` درج می‌کنه. اگه تکراری باشه، کاری انجام نمی‌ده.
2. مبلغ، ارز و `booking_id` رو چک می‌کنه.
3. نوبت رو `confirmed` می‌کنه. این کار حتی اگه نوبت `expired` شده باشه انجام می‌شه، به شرطی که ساعت هنوز آزاد باشه.
4. ردیف `payments` با وضعیت `paid` می‌سازه.
5. ایمیل تأیید و یادآوری‌های آینده رو به صف اضافه می‌کنه.
6. **اگه ساعت گرفته شده باشه:**
   - پرداخت ثبت می‌شه.
   - یه کار `refund` به صف اضافه می‌شه.
   - به ادمین هشدار داده می‌شه.
   - نوبت قطعی **نمی‌شه.**

**`reschedule_booking(booking, new_starts_at, actor)`**
1. اجازه‌ی جابه‌جایی رو طبق ۴-۷ چک می‌کنه.
2. زمان همون ردیف رو `UPDATE` می‌کنه. اگه به تداخل بخوره، کل کار برمی‌گرده.
3. سابقه رو ثبت می‌کنه.
4. یادآوری‌های قدیمی رو لغو می‌کنه و یادآوری‌های جدید می‌سازه.

**`cancel_booking(booking, actor, reason)`**
1. ردیف مربوط به جدول ۴-۸ رو پیدا می‌کنه.
2. اگه لازم باشه، طلب `late_cancel` رو با `source_key` یکتا ثبت می‌کنه.
3. اگه لازم باشه، کار `refund` رو به صف اضافه می‌کنه.

**`finalize_session(booking)`**
1. نتیجه رو طبق ترتیب ۴-۸ تعیین می‌کنه.
2. طلب مربوط رو با `source_key` یکتا ثبت می‌کنه. پس اگه دو بار صدا زده بشه، اثرش یه بار حساب می‌شه.

**`record_settlement(...)`**
- تسویه رو ثبت می‌کنه.
- سابقه‌ی تغییرات رو ثبت می‌کنه.

**`claim_jobs(n)`**
- `n` کار آماده رو با `FOR UPDATE SKIP LOCKED` برمی‌داره و قفل می‌کنه.
- کار ناموفق با فاصله‌ی زمانی رو به افزایش دوباره امتحان می‌شه.
- بعد از ۵ بار شکست، `failed` می‌شه.

### ۷-۷. Webhook‌ها

**Stripe**
- `checkout.session.completed`: فقط وقتی `payment_status = paid` باشه.
- `charge.refunded` و `refund.updated`: برای به‌روزرسانی `refunds` و `payments.refunded_cents` و وضعیت پرداخت.
- `charge.dispute.created`: وضعیت پرداخت رو `disputed` می‌کنه و به ادمین هشدار می‌ده.
- `charge.dispute.closed`: وضعیت پرداخت رو برمی‌گردونه یا برگشت ثبت می‌کنه.
- کارمزد واقعی از balance transaction خونده می‌شه و توی `fee_cents` ذخیره می‌شه.

**سرویس تماس**
- رویدادهای `joined` و `left` با شناسه‌ی یکتا ثبت می‌شن.

### ۷-۸. ساعت‌ها
- برنامه‌ی هفتگی به ساعت تهران ذخیره می‌شه.
- وقت‌های خالی روی سرور به UTC تبدیل می‌شن.
- مرورگر مراجع اون‌ها رو به ساعت محلی خودش نشون می‌ده.
- **تست‌ها** باید روز تغییر ساعت تابستانی آمریکا و اروپا رو هم پوشش بدن.

### ۷-۹. پیشنهاد دکتر

**فیلترها**
- فقط دکترهای فعال.
- جنسیت دلخواه مراجع: فقط اگه نتیجه‌ای داشته باشه اعمال می‌شه. اگه نتیجه خالی بشه، این فیلتر برداشته می‌شه و یه پیغام نشون داده می‌شه.

**امتیازها**
- تطابق تخصص با موضوع مراجع
- داشتن وقت خالی توی ۷ روز آینده
- امتیاز اضافه اگه وقت خالی توی عصر مراجع (۱۷ تا ۲۲ به ساعت محلی خودش) باشه. **این فقط امتیازه، فیلتر نیست.**

## ۸. امنیت و قوانین

**رمزگذاری**
- جواب‌های پرسشنامه و یادداشت‌های دکتر با AES-GCM (WebCrypto) رمزگذاری می‌شن.
- کلید فقط روی سرور نگه داشته می‌شه.

**یادداشت‌های دکتر**
- هیچ‌جای پنل آژانس نمایش داده نمی‌شن و ادمین هیچ policy‌ای روشون نداره.
- صادقانه: صاحب سایت از نظر فنی به سرور و کلید دسترسی داره. پس این یه تعهد طراحیه، نه قفل ریاضی.

**تماس**
- ضبط نمی‌شه.
- توکن ورود به تماس رو سرور خودمون صادر می‌کنه و کوتاه‌مدته.
- اتاق فقط از ۱۰ دقیقه قبل از جلسه تا ۳۰ دقیقه بعد از پایانش باز می‌مونه.

**پاک‌سازی**
- پرسشنامه‌های مهمان بعد از ۷ روز پاک می‌شن.

**متن‌های قانونی**
- سرویس «مشاوره و روان‌درمانی آنلاین» معرفی می‌شه.
- شفاف نوشته می‌شه که این سرویس اورژانسی نیست و نسخه صادر نمی‌کنه.
- این صفحه‌ها ساخته می‌شن: حریم خصوصی، شرایط استفاده، کنسلی، شرایط اضطراری.
- پذیرش هر متن با نسخه‌ش ثبت می‌شه.

**⚠️ موارد قانونی که صاحب سایت عمداً عقب انداخته**
- محدودیت‌های Stripe برای خدماتی که منشأشون ایرانه
- تحریم‌ها
- مجوز فعالیت در کشور مراجع
- قوانین حفاظت داده

ساخت و پایلوت منتظر این موارد نمی‌مونن. فقط **شروع پول واقعی** (قدم ۷) منتظر تصمیم خود صاحب سایت می‌مونه. تا اون موقع Stripe روی حالت تست کار می‌کنه.

---

## ۹. تست تماس از ایران (قدم ۰-الف)

**روش تست**
1. یه صفحه‌ی آزمایشی روی Cloudflare ساخته می‌شه که با Daily، LiveKit Cloud و Cloudflare Realtime تماس برقرار می‌کنه.
2. برای هر سرویس، چند تماس ۵۰ دقیقه‌ای گرفته می‌شه:
   - شبکه‌ها: اینترنت خونگی، همراه اول، ایرانسل
   - دستگاه‌ها: لپ‌تاپ و گوشی
   - با قطع و وصل عمدی
   - با حالت فقط صدا
   - با TURN روی پورت ۴۴۳

**معیار انتخاب**
- درصد تماس‌هایی که بدون قطعی طولانی تموم شدن
- کیفیت صدا (مهم‌تر از تصویر)
- سرعت وصل شدن دوباره
- هزینه

**شرط عبور:** صاحب سایت و یه دکتر داخل ایران بگن «این کیفیت برای جلسه‌ی واقعی قابل تحمله».

**اگه هیچ‌کدوم جواب نداد:** LiveKit یا Jitsi روی سرور خودمون جداگانه سنجیده می‌شه. این راه هم تضمینی نیست.

کد این صفحه‌ی آزمایشی بعداً پاک می‌شه.

## ۱۰. خطاها و پشتیبان

**رزرو و جابه‌جایی**
- **دو رزرو هم‌زمان:** نفر دوم پیغام «این ساعت همین الان رزرو شد» می‌بینه.
- **جابه‌جایی ناموفق:** نوبت قبلی بدون تغییر می‌مونه.

**پرداخت**
- **پرداخت دیرهنگام:** طبق `confirm_payment` رسیدگی می‌شه.
- **برگشت ناموفق:**
  - ۳ بار دوباره امتحان می‌شه.
  - بعد وضعیت `refund_pending` می‌مونه و به ادمین هشدار داده می‌شه.
- **رویدادهای تکراری یا خارج از ترتیب:**
  - رویدادهای Stripe با `stripe_events` و رویدادهای تماس با `provider_event_id` یکتا شناسایی می‌شن، پس تکرارشون اثری نداره.
  - تصمیم‌ها از روی وضعیت فعلی گرفته می‌شن، نه ترتیب رسیدن رویدادها.

**طلب دکتر**
- **دو بار ثبت شدن نتیجه:** با `source_key` یکتا جلوش گرفته می‌شه.

**صف کارها**
- هر کار قفل می‌شه، پس دو Cron هم‌زمان یه کار رو دو بار انجام نمی‌دن.
- کار ناموفق توی داشبورد دیده می‌شه.

**پشتیبان**
- پشتیبان روزانه‌ی Supabase (پلن Pro).
- `pg_dump` هفتگی رمزگذاری‌شده روی R2.
- **قبل از پایلوت:**
  - بازیابی کامل روی یه پروژه‌ی جدا یه بار واقعاً انجام می‌شه.
  - با کلید رمز، یه ردیف پرسشنامه و یه یادداشت باز می‌شن تا مطمئن بشیم داده‌ی رمزشده هم قابل بازیابیه.

## ۱۱. تست‌ها

### واحد (Vitest)
- ساخت وقت خالی، شامل روزهای تغییر ساعت آمریکا و اروپا
- فاصله‌ی استراحت، حداقل و حداکثر فاصله‌ی رزرو، و الزام تیک برای نوبت‌های ۱۲ تا ۲۴ ساعت
- سهم درصدی و ثابت، و رد شدن سهمی که سهم آژانس رو منفی می‌کنه
- محاسبه‌ی زمان هم‌زمان با قطع و وصل
- ترتیب تعیین نتیجه، شامل:
  - زمان هم‌زمان بالا + دکمه‌ی اتصال ← `completed`
  - زمان هم‌زمان پایین ← `partial`
- جدول کنسلی
- مانده و تخصیص، شامل پرداخت اضافه به دکتر
- پیشنهاد دکتر:
  - عصرِ آمریکا لیست رو خالی نمی‌کنه.
  - جنسیتی که نتیجه نداره، فیلترش برداشته می‌شه.

### دیتابیس (PGlite)
- دو `hold_slot` هم‌زمان روی یه بازه
- تداخل با فاصله‌ی استراحت
- پرداخت دیر:
  - وقتی ساعت هنوز آزاده ← قطعی می‌شه
  - وقتی ساعت گرفته شده ← برگشت می‌خوره، و دو نوبت قطعی ساخته نمی‌شه
- جابه‌جایی ناموفق
- جابه‌جایی با یه پرداخت (بدون ساخته شدن ردیف پرداخت دوم)
- دو بار صدا زدن `finalize_session`
- RLS:
  - مراجع و دکتر داده‌ی بقیه رو نمی‌بینن
  - دکتر `payments` رو نمی‌بینه
  - ادمین بدون `aal2` هیچی نمی‌بینه
  - ادمین `doctor_notes` رو نمی‌بینه
  - کاربر نقشش رو عوض نمی‌کنه
  - view دکتر با `security_invoker` ستون مالی لو نمی‌ده

### یکپارچه
- webhook: تکراری، خارج از ترتیب، مبلغ اشتباه، پرداخت دیرهنگام، اعتراض بانکی
- برگشت ناموفق
- قفل صف و تکرار کار

### مرورگر (Playwright)
- مسیر کامل با کارت تست: پرسشنامه ← رزرو ← پرداخت ← جلسه ← نتیجه ← کنسلی ← برگشت ← تسویه
- نوبت ۱۲ تا ۲۴ ساعت بدون تیک جلو نمی‌ره
- زدن دکمه‌ی اتصال توی جلسه‌ی طولانی، طلب دکتر رو پاک نمی‌کنه

### قبولی پایلوت
- دست‌کم ۹۰٪ جلسه‌ها بدون جابه‌جایی به خاطر اتصال تموم بشن.
- هیچ ویرایش دستی توی دیتابیس لازم نشه.
- جمع دفتر با گزارش تست Stripe بخونه.
- هر مشکل اتصال توی ساعت‌های پشتیبانی جواب بگیره.
- هر مراجع دعوت‌شده دست‌کم یه جلسه رو خودش، بدون پیام دستی، رزرو کنه.

### قبولی شروع پول واقعی
- صاحب سایت تصمیم مثبت گرفته باشه.
- پایلوت قبول شده باشه.
- یه تسویه‌ی واقعی با رسید توی دفتر ثبت شده باشه و مانده رو درست کم کرده باشه.

### قبل از تبلیغات پولی
- حدود ۸ دکتر فعال داشته باشیم که عصرهای اروپا رو پوشش بدن.
- چند مراجع جلسه‌ی دوم رو خودشون رزرو کرده باشن.
